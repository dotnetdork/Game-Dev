Great designers plan before coding. For your game, jot down: the **sprites** (player, enemies, items), the **rules** (how you score, how you lose), and which **systems** you need (input, physics, UI). This is exactly the designer's job from Module 4.

Order a simple planning process:

```quiz
type: parsons
prompt: Order a sensible plan-then-build process.
lines:
  - Decide the goal and how you win or lose
  - List the sprites you need
  - Build the core loop first
  - Add challenge, then polish
```
